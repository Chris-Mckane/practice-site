# Notes for AI assistants working on this repository

Personal brand site for Chris McKane: EmDash CMS (1.5) on Astro 7, hosted on Cloudflare Workers
with D1 (database), R2 (media), KV (sessions) and Workers Cache (edge cache of rendered HTML).

The owner is a digital marketing strategist (web performance, SEO, design, CRO), not a developer.
Explain technical points in plain English. `GUIDE.md` is his manual: keep it accurate when
behaviour changes, and add to its "Decisions log" when you make a judgement call.

## Commands

```bash
npm run dev             # local dev server (Cloudflare runtime) at http://localhost:4321
npm run build           # production build
npm run preview         # serve the production build locally
npm run typecheck       # astro check (must stay at 0 errors)
npm run check:contrast  # WCAG AAA contrast check of every colour pairing
npm run check:seed      # validate seed/seed.json
cd tools/verify && npm install && node verify.mjs   # Lighthouse, axe, outlines, weights (needs `npm run preview` running)
```

Local first run: open `/_emdash/api/setup/dev-bypass?redirect=/_emdash/admin` under `npm run dev`.
It applies the seed and signs you in as a development administrator.

## Map

| Path | Purpose |
| --- | --- |
| `astro.config.mjs` | EmDash options, edge cache rules (`routeRules`), self-hosted fonts, the build step that trims unused EmDash CSS |
| `wrangler.jsonc` | Cloudflare bindings. The Worker name must stay equal to the Cloudflare project name |
| `seed/seed.json` | Content model (collections, block types, taxonomy, menus) and Lorem ipsum content. Applied once at first setup |
| `emdash-env.d.ts` | Types generated by EmDash from the schema. Regenerated by the dev server. Do not edit by hand |
| `src/middleware.ts` | Indexing switch: `X-Robots-Tag` and `robots.txt` while the site is in staging |
| `src/lib/site.ts` | Site-wide data: settings, Site options (availability mode), menus. Registers cache tags |
| `src/lib/jsonld.ts`, `src/lib/seo.ts` | Structured data and per-entry SEO |
| `src/layouts/Base.astro` | Page shell and `<head>` |
| `src/components/PageSections.astro` | Maps each block type to its component in `src/components/blocks/` |
| `src/pages/` | Routes: `/`, `/[slug]`, `/blog`, `/blog/page/[page]`, `/blog/category/[slug]`, `/blog/[slug]`, `/rss.xml`, `/sitemap.xml`, `404` |
| `src/styles/` | Plain CSS, imported by the component that needs it so each page gets only its own styles |
| `tools/verify/` | Verification tooling with its own `package.json` (never installed by Cloudflare builds) |
| `tools/local/` | Local helpers: screenshots, layout-shift tracing, seed generator, placeholder image upload, switch tests |
| `HANDOVER.md` | State of the project, what was rejected (the visual design) and everything learned about the platform. Read it first |
| `.agents/skills/` | EmDash's own skills for AI assistants (copied from the official templates). Read `building-emdash-site` before touching content queries or the seed |

EmDash documentation: https://docs.emdashcms.com (also available as an MCP server, see `.mcp.json`).
Check it rather than relying on memory: EmDash, Astro and Cloudflare all move quickly.

## Rules that must keep holding

**Content**
- No hard-coded copy except tiny interface microcopy. Every heading, paragraph, button label and URL,
  menu item, image and SEO field comes from EmDash.
- Never invent facts, statistics, clients or testimonials. Placeholder text is Lorem ipsum or marked `[Placeholder]`.
- Give every collection, field and block type a clear label and description: editors and AI tools (through
  EmDash's MCP server) rely on them.
- When the content model changes, update `seed/seed.json` too so a fresh install matches production.

**Headings**
- Exactly one H1 per page, then H2, then H3, never skipping a level. Size comes from classes
  (`.h-hero`, `.h-page`, `.h-section`, `.h-item`), never from the choice of tag.
- Blocks that can carry the H1 are listed in `H1_BLOCKS` (`src/lib/blocks.ts`); the first one on a page gets it.
- Rich text is rendered through `src/components/Prose.astro`, which keeps headings to H2 and H3.

**Performance budgets** (measured in `VERIFICATION.md`)
- Inline CSS under 15 KB per page. Inline JavaScript under 3 KB in total. No external scripts, no client
  framework, no third-party requests. Homepage HTML under 30 KB compressed.
- CLS must be exactly 0. Fonts use `font-display: optional` with preload. Reserve space for anything
  that fills in later (see the proof badge).
- Images go through `src/components/Photo.astro` (EmDash's image component, AVIF and WebP, explicit size).
  `priority` only on an image that really is the largest element in the first screen.
- Every public route needs an edge cache rule in `astro.config.mjs` (or `Astro.cache.set` in the page)
  and must pass each query's `cacheHint` to `Astro.cache.set()` so publishing purges it.
  Redirects must call `Astro.cache?.set(false)`.
- Use the configured Site URL (`site.url`) for absolute URLs, never `Astro.url.origin`: the edge cache is
  shared across hostnames.

**Accessibility (WCAG 2.2 AAA where feasible)**
- Text contrast at least 7:1 in both themes, including hover states. Run `npm run check:contrast` after
  any colour change.
- Visible 3px focus ring, 44 by 44 pixel minimum for stand-alone links and buttons, skip link, landmarks,
  `lang="en-GB"`, all motion disabled under `prefers-reduced-motion`.
- Images without alt text are not rendered. Links do not open new tabs.
- Zero axe-core violations.

**Design**
- Palette "ink and mint": mint (emerald in the light theme) is an accent only, never a large surface.
- Avoid: coloured left borders, grids of bordered cards, uppercase letter-spaced labels, numbered "01 / 02"
  markers, pill badges, gradient blobs, emoji icons, an italic serif word inside a sans headline.
- UK English.

**Workflow**
- Work on a branch and open a pull request. Merging to `main` deploys automatically through Cloudflare Workers Builds.
- Never ask the owner to paste secrets into a chat. Secrets go in Cloudflare (Worker settings, Variables and Secrets).
- After design or template changes, run the type check, the contrast check and the verification suite, and
  update `VERIFICATION.md`.
